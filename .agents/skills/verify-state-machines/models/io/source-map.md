The former interrupted-download finding is fixed by commit 94487cf and CSV streaming publication in 14b3363. `FailurePreservesDestination` is now a baseline invariant with a failing truncation mutant. Actual command replays start with valuable existing bytes, fail after a partial response, and assert the original file remains intact. CSV replay also checks complete replacement, preserved permissions, cancelled publication and removed temporary files. It no longer asserts obsolete whole-response buffering.

`Multipart.finding.cfg` still demonstrates that caller return need not mean producer cleanup has already run. This is a scheduling fact, not a leak claim. The UNIX replay checks eventual cleanup after malformed request creation without forcing the exact interleaving. Progress may return on cancellation while the request goroutine finishes later; buffered result delivery prevents it waiting on a receiver. Callbacks are synchronous and a callback that never returns can delay cancellation. No stronger cancellation or scheduling claim is made.

`HTTP.finding.cfg` demonstrates that raw Request and multipart add no fixed deadline. StreamGet has a distinct default 24 hour transfer deadline. Custom RoundTripper replays inspect actual contexts and cancellation before dispatch.

Each baseline invariant has a matching model mutant. Atomic publication mutants truncate early or publish incomplete/unclosed data; stdout mutant treats short writes as success; timeout and cancellation mutants remove their guards; multipart mutants omit cleanup or reverse its order; progress mutant overstates accepted bytes. These establish model sensitivity and do not substitute for source mutation testing.

Run `python3 models/io/mutate_real.py DISPOSABLE_REPO LOG_DIRECTORY` from the skill directory after installing replay-map tests. It checks three faults and restores source before rerunning the baseline. Exact source mutations supported by replay tests include replacing `os.CreateTemp(filepath.Dir(destPath), ".bookbeam-download-*")` in saveDownload with `os.Create(destPath)`, replacing StreamGet's `context.WithTimeout(ctx, c.TransferTimeout)` with `context.WithCancel(ctx)`, removing saveDownloaderCSV's post-close `ctx.Err()` guard, and removing Proceed's `|| p.JSON` authorization guard. Each is a deliberate fault for a disposable source copy. The csvWriter short-write replay checks the returned error and absent confirmation. io.Copy itself also detects short writes, so removing csvWriter's redundant short-write guard alone is not claimed as a detectable behavioral fault.

All models prove bounded safety only. Scheduler fairness, process crashes, fsync durability, races with other filesystem writers, TLS, HTTP internals, external browser success and server persistence remain outside the models. A killed process can leave a hidden temporary file without publishing partial data.
