## Findings and concrete replays

ReadMergeWrite.finding.cfg checks PreserveConcurrentEdit and fails. The CLI reads an unedited field, another writer changes it, then the CLI sends the old field in its full PUT. TestFormalStaleLinkOverwriteReplay and TestFormalStaleNewsletterOverwriteReplay use the actual Cobra handlers and HTTP client. The fixture changes the remote field after GET and records the subsequent PUT. They prove the CLI emits stale values. The overwrite depends on a server accepting unversioned last-write-wins PUT; production server behavior is outside scope.

RemoteRequests.finding.cfg checks ErrorMeansNoMutationRequest and fails. A successful create request can be followed by malformed JSON and a local error. TestFormalRemoteCreateThenDecodeFailureReplay sends through the actual handler/client and records the request before returning malformed JSON. This proves that a local error is insufficient evidence that no remote request ran. The fixture's create counter represents a committed operation only under the stated server assumption. No claim of production data loss or rollback is made.

The replays intentionally pass by confirming the current counterexamples. They must not be misreported as desired-property passes.

## Refresh against current main
